EmulatorOS is a fully static, open-source gaming platform that runs entirely in the browser — no servers, no downloads, no accounts required. It combines two independent pillars under one roof: a curated library of 100+ HTML5 web games playable directly in an `<iframe>`, and a deep retro console emulation layer powered by EmulatorJS (a WebAssembly port of the libretro/RetroArch ecosystem). Both pillars are served from GitHub Pages at zero infrastructure cost. The platform ships as **v1.4.0** (semantic versioning: Major.Minor.Patch, defined in `main.js`) and is installable as a Progressive Web App, meaning players can pin it to their home screen and continue playing offline.

## Platform Architecture

EmulatorOS is deliberately simple: every file is static, meaning the entire platform deploys with a single `git push` to GitHub Pages. The emulation engine itself lives under `data/` — `loader.js` reads `EJS_*` globals set on the page, dynamically injects the minified engine bundle and stylesheet, then hands control to the `EmulatorJS` class. Save data is persisted in the browser's IndexedDB filesystem (`IDBFS`) at `/data/saves`, so progress survives page refreshes without any backend.

<Info>
  EmulatorOS version **v1.4.0** is the current stable release. The version string is assembled at runtime from the semantic array `['1', '4', '0']` in `main.js` — bumping any element triggers downstream version-awareness logic across the platform.
</Info>

## Deployment Model

The platform targets **GitHub Pages** as its primary host. Because everything is static HTML, CSS, and JS, it can also be served from any CDN, Netlify, Vercel, or a local HTTP server with no build step required. There is no Node.js build pipeline, no bundler, and no server-side logic.

<Note>
  GitHub Pages enforces HTTPS, which is a hard requirement for service workers and the `beforeinstallprompt` PWA install event. Running the site over plain `http://` will silently disable both PWA install prompts and offline caching.
</Note>

## Localization

The emulation UI supports 14 languages via JSON translation files in `data/localization/`. Set the `EJS_language` global before loading `loader.js` to activate a locale. Available locales are: `af-FR`, `ar-AR`, `ben-BEN`, `de-GER`, `el-GR`, `en`, `es-ES`, `hi-HI`, `ja-JA`, `jv-JV`, `ko-KO`, `pt-BR`, `ru-RU`, and `zh-CN`.
